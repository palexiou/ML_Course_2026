# MALTAomics historical source review

Research date: 2026-11-03. Scope: historical teaching evidence and recommendations; no course/deck changes.

**Main finding:** this is useful teaching context, especially for showing a model developing across several slides. The strongest direct precedent for the logistic pilot is the 2023 deep-learning workshop's sequence **numeric DNA input → weighted sum z → sigmoid probability → sigmoid curve** (PDF pp. 23–31). The repository also contains genuine protein-language-model embedding exercises. Its coding-agent relevance is limited to general AI discussion and a ChatGPT prompting screenshot; it does not supply the current Day 4 agent workflow.

## Teaching patterns worth carrying forward

### 1. Keep the object in place and reveal one operation

**Observed:** DL p. 29 shows one-hot bases feeding weights and a summed score **z**. Page 30 retains that model and adds **sigmoid(z)** and an output probability. Page 31 enlarges the sigmoid curve. Earlier, p. 7 already established inputs/weights/sum/bias; pp. 10, 13, 24 and 32–38 reuse the training-loop drawing while discussing another component. These are actual figures, not conclusions drawn from filenames. [DL][dl].

**Apply to outline 09 / current guide D1 28–31 and the logistic pilot:** retain one drawing across about four or five focused slides: count inputs → signed weighted contributions plus bias → z → sigmoid and p → threshold decision. Use the existing guide's declared illustration, **z = 1, p ≈ 0.731**, rather than introduce another numerical example. Keep feature colors, positions and connectors stable; enlarge the currently explained operation. If there is an interaction, make its role explicit: changing an input while weights stay fixed is prediction; changing weights using training labels is fitting.

Suggested speaking cues, rather than abstract slogans: “Each count contributes count × weight”; “The bias is the starting offset”; “z can be any real number”; “The sigmoid maps z to a model probability”; “A threshold turns that probability into a decision.” Ask “One more TATA count adds how much?” before revealing +0.6. Ask “What is p when z is zero?” before revealing 0.5. These cues implement the instructor's request for a visually appealing explanation they can follow. They are recommendations, not verbatim historical notes.

### 2. Make the representation visible before naming the architecture

**Observed:** DL pp. 23–26 progress from “how can DNA enter this model?” to base IDs and one-hot columns. The readable second Drive notebook follows the same path: cells 1–5 inspect integer encoding, one-hot shape, flattening, a linear layer, and a linear-plus-sigmoid classifier. Its real dataset then appears in cells 9–12. [DL][dl], [MALTA_02][drive2].

**Apply to outline 05–06 and 21:** use the same short sequence across windows, count vector and model-input diagrams. Day 1 needs **k-mer counts**, whereas the historical classifier uses **flattened positional one-hot inputs**; do not describe those as the same representation. On Day 2, rebuild one-hot encoding visibly and identify the channel/position axes. This gives the existing data-inspection practical a teachable purpose: identify x, y and the shape/content of x before calling `fit`.

### 3. Work through a tree, then explain why there are many

**Observed:** Ebejer's RF pp. 5 and 7 connect a decision path to feature-space partitions; p. 9 supplies a small weather/swimming table; pp. 21→22→23 select a first split, show the resulting subsets and finish the tree. Pages 24–25 introduce bootstrap samples, feature sampling and aggregated tree predictions. [RF][rf].

**Apply to outline 13 / D1 43–46:** use a small invented k-mer table and follow one example down one branch per slide. Let students choose a branch before revealing it. Show two slightly different trees before the forest aggregates their outputs. Retain a short explanation of what makes a learned split useful; the historical multi-page entropy calculation is optional background, not necessary arithmetic for this cohort. Explain probability aggregation consistently with the actual scikit-learn classifier rather than implying all implementations only take hard majority votes.

### 4. Teach metrics through a concrete change in the prediction problem

**Observed:** Alexiou's CNN slides 11–14 retain the hairpin-versus-background boxes while changing a balanced mixture to rarer positives and a background-only search. The spoken-style definitions on slide 13 connect precision to positive calls and recall to finding actual hairpins. RF pp. 28–31 connect a contingency table, an always-negative Nobel-prize predictor, imbalance and precision/recall/F1. [CNN][cnn], [RF][rf].

**Apply to outline 02 and 10 / D1 32–39:** preserve the guide's one consistent 100-example confusion matrix; progressively highlight each metric's numerator and denominator. A later brief “many more negatives” illustration can make the reason for precision memorable. Do not import genome scanning as the practical, reproduce historical scores, or open with a long evaluation warning. Teach what the quantities mean first, then show why accuracy alone can hide missed positives. The historical examples motivate the concept; they do not change the accepted course dataset.

### 5. Pair a plot with a small question students can answer

**Observed:** permutation-importance cells 23–30 define score decrease, calculate repeated permutations and plot variability; cell 31 asks what shuffling changes and how to interpret a score decrease. Cells 33–46 add correlated toy features to expose an interpretation trap. The RF practical cells 7, 16–24 move through a feature table, fitting, labels, probabilities, confusion matrix, feature importances and one actual tree. [PFI][pfi], [RF practical][rf-notebook].

**Apply to outline 14–15 / D1 47–54:** make the prompt specific: “Which counted fragments overlap the planted motif?” and “Would correlated fragments share credit?” Have students point to a bar and give one sentence about the predictor. Keep the training/validation split and known simulation truth in the illustration. Additional SHAP software is unnecessary for this learning outcome. If permutation importance becomes an extension, calculate it on **validation**, not the protected test, and explain correlations with the overlapping k-mers.

## Relevant Days 2–4 material and limits

**Day 2: real explanatory depth is available.** DL pp. 39–41 distinguish stacked linear operations from a network with ReLU. Pages 49–50 contrast position-specific dense connections with a shared local detector; pp. 51–67 move a **CCG** pattern through one sequence, then express the operation with a one-hot matrix and filter. Pages 71–77 add learned filter weights, multiple feature maps and local max pooling. The second Drive notebook cells 25/29 contain MLP/CNN blanks, and cells 34/35 contain solutions; cell 30 changes flattened one-hot inputs into channel×position arrays. Borrow the small steps and selected-code exercise pattern. Keep our actual 4×160 input and the position-aware CNN; historical local pooling is not a demonstration of our combined flatten/global-max architecture. [DL][dl], [MALTA_02][drive2].

Grešová's pp. 23→24 keep input and score in place while changing handcrafted feature extraction into learned extraction; pp. 27→29 develop image explanations into sequence/interaction questions; pp. 33→35 retain a predicted alignment while adding position importance and a biological cartoon. These support the current controlled-sequence-change discussion through a visible input change and predictor response. They do not require adding a full attribution-method practical. [Deep XAI][deep-xai].

**Day 3: embeddings and fine-tuning are genuinely present.** Šrámková's pp. 40–51 develop sequence→vector→comparison→downstream model; pp. 56–62 progressively explain tokenization; pp. 79 and 85–89 distinguish extracted features from updating pretrained weights. Extraction notebook cells 11–19 load a tokenizer/model and compute representations; training notebook cells 6–14 load cached embeddings and fit a CNN; fine-tuning cells 6–17 load a sequence classifier and run a Trainer. Use these to strengthen explanations of which weights change and how one sequence becomes one reusable vector. Keep our DNA checkpoint, explicit pooling, aligned IDs, cached full-data extraction and simple downstream classifier. [Protein slides][protein], [extraction][embedding], [training][embedding-training], [fine-tuning][finetuning].

Alexiou's CNN slides 34–35 explicitly name foundation models for genomics and include screenshots for **DNABERT-2, Nucleotide Transformer, scGPT**, and a critical paper on regulatory-genomics foundation models. This is historical awareness of the field, not an implementation of our present NT-v2 workflow. There is no basis here to transplant a 2023 benchmark score into the course. [CNN][cnn].

The supplied local [transformer presentation](/home/palexiou/ml-presentation-style-review/transformers.pdf) remains a closer style/content reference for Day 2's **nonlinear relationship→ReLU→hidden layer** (slides 2–4) and Day 3's **generic embedding→attention arrows→contextualized embedding** (11–13). I inspected the existing rendered contact sheets; no new extraction was needed. The historical material reinforces that approach. Avoid inheriting simplified claims that all embeddings automatically preserve biological similarity or that BERT is an encoder–decoder model. Distinguish per-token vectors from a pooled sequence embedding.

**Day 4: use the historical context sparingly.** The round-table ChatGPT screenshot is a concrete example of asking an LLM for discussion starters. It supplies neither agent execution evidence nor a coding-agent teaching sequence. Preserve the current separately evidenced demonstrations, specification/instructions/skill distinctions and scientific audit. Do not attribute AGENTS.md, tools, autonomous experimentation or Agentomics content to this repository. [Round table][roundtable].

## Priorities for the parent and pilot

1. **Make the logistic explanation one evolving visual across several focused slides.** Use DL pp. 29→30→31 as the clearest historical precedent, and retain the guide's one worked count/weight example. Notes should explain each operation, ask one answerable question, give its answer, then bridge to the next operation. The pilot should test whether this makes the model understandable before adding more content.
2. **Use the same progression for trees, metrics and neural representations.** Keep the existing course sequence; develop a path/partition, highlight confusion-matrix denominators, and move one detector along one DNA string. The historical sources support teaching mechanisms concretely. A warning about scientific validity should follow a model or result students understand, rather than occupy its explanatory slot.
3. **Reuse Day 3's conceptual bridge, with our modern implementation and protocol.** Protein embeddings/fine-tuning provide a real historical foundation; the supplied transformer slides offer the stronger attention story. Keep the simulation and protected-test contract, fix rather than inherit historical preprocessing/evaluation shortcuts, and develop Day 4 from its actual agent evidence.
